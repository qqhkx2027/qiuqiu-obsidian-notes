# Obsidian 笔记标准

## 目标目录与命名

- 常青卡片默认保存到 `03-Resources/Evergreen/`。
- 文件名等于原子化核心词，例如 `费曼学习法.md`。
- 不在文件名中添加日期、序号、emoji 或“常青笔记”等冗余后缀。
- 正文不再添加与文件名重复的 `# 一级标题`。

## YAML 属性

沿用知识库现有字段：

```yaml
---
name: 核心词
description: "常青卡：一句话核心价值"
category:
  - "[[常青卡片]]"
tags: [心智模型/元认知与思维方法论]
source: []
status: ToDo
---
```

规则：

- `name` 与文件名一致。
- `description` 简短、可独立理解；包含冒号等特殊字符时加引号。
- `category` 默认只使用 `[[常青卡片]]`。
- `tags` 保存芒格多元思维模型格栅标签，必须从 [mental-model-tags.md](mental-model-tags.md) 的规范表选择 1–5 个。
- 不新增 `mental_models` 或其他平行标签属性；所有心智模型标签统一写入 `tags`。
- `source` 保存用户提供的 URL、书籍、文章或源笔记；没有来源时使用 `[]`，不得编造。
- `status` 默认 `ToDo`；只有用户明确给出其他状态时才改变。

## 双向链接

1. 写关系节前，先用文件名和内容搜索 `03-Resources/Evergreen/`。
2. 链接使用 `[[准确文件名]]`；显示文字不同时使用 `[[文件名|显示文字]]`。
3. 不把普通高频词全部链接化；只链接对理解或导航有帮助的概念。
4. 不创建指向虚构卡片的链接。用户明确希望规划未来卡片时，可以保留少量待建链接并在交付时说明。
5. 不为建立反向链接而擅自修改大量旧笔记；只有用户要求时才更新关联文件。

## Callout 映射

| 内容 | Callout |
| --- | --- |
| 问题、风险、痛点 | `> [!warning]` |
| 真实案例或类比 | `> [!example]` |
| 步骤与行动清单 | `> [!check]` |
| 用户内化提示 | `> [!abstract]` |

不要用 `---` 分割正文各节，也不要为了好看堆叠 callout。

## 新建与更新

### 新建前

- 检查同名文件、别名和近义概念。
- 读取相关卡片，确认是否应该更新旧卡而不是创建重复卡。
- 检查目标目录和文件名不包含非法路径字符。

### 更新时

- 先读取完整原文件。
- 保留用户填写的内化、真实经历、人工批注、来源和有效双链。
- 采用增量修改，不用新模板粗暴覆盖整篇。
- 若新版结构与原文冲突，先说明将移动或改写哪些内容。
- 只做心智模型打标时，仅把规范标签合并进原 `tags` 并去重；保留原有其他标签和正文，不静默删除旧标签。

### 写入后

- 确认 YAML 可解析、七节 H2 不重复、Markdown 表格列数一致。
- 确认所有内部链接语法闭合。
- 回报绝对文件路径、新建或更新状态、关键链接与待用户填写项。

## 事实与来源

- 优先使用用户素材和知识库已有笔记。
- 涉及研究、年份、统计数字和引文时必须可追溯；无法核实时删除具体数字或标注“待查”。
- 不把经验模型包装成科学定律。
- 不复制来源中的长段文字，用自己的话重新组织。
