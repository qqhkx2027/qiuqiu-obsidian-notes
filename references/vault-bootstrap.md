# Vault 文件夹引导

用于“从 0 到 1 搭建 Obsidian”“参考我的笔记生成文件夹”“重建目录结构”等任务。目标是从用户已有笔记中提炼个人信息架构，而不是套用一份脱离实际的通用模板。

## 核心原则

- 先理解现有 Vault，再提出新增结构。
- 文件夹服务于检索、写作和归档，不按理论强行拆分。
- 目录规划与笔记迁移是两件事；默认只创建文件夹，不移动或重命名旧笔记。
- 任何创建动作都必须经过用户确认。
- 空文件夹可以创建，但不自动生成占位笔记或示例文件。

## 扫描范围

按以下顺序读取，控制上下文和隐私暴露：

1. Vault 根目录的一级、二级文件夹名称。
2. 各一级目录的 Markdown 数量、最近修改分布和文件类型。
3. 每个主要目录抽取 3–10 个代表性笔记：只先读 YAML、标题和前 80–120 行。
4. 读取用户指定的结构说明、索引页、README 或模板。
5. 只有需要判断归属时，才深入读取更多正文。

不要把 `.obsidian/`、`.git/`、`.trash/`、缓存、插件构建产物和私人凭据当作内容目录分析。

## 结构推断

为每个现有目录判断其主要职责：

| 线索 | 可能职责 |
| --- | --- |
| 待办、目标、项目交付、进行中 | Projects / 项目 |
| 持续维护的领域、健康、工作、家庭 | Areas / 领域 |
| 已完成、暂不活跃但需要保留的项目与资料 | Archives / 归档 |
| 长期可复用概念、知识卡片、心智模型 | Evergreen / 常青知识 |
| 书籍、论文、网页、剪藏原文 | Resources / 资料 |
| 日记、周报、复盘、阶段记录 | Logs / Growth / 日志成长 |
| 图片、附件、脚本、模板 | Attachments / 素材 |
| AI 原始输入、主题研究、分类总库 | LLM-WiKi / AI 知识处理 |
| 技能、自动化、工作流说明 | Agents / Skills |

这是推断表，不是必须采用的命名。最终命名优先保留用户现有中文、编号、大小写和层级习惯。

## 从 0 到 1 工作流

### 1. 扫描

输出当前目录树、每个目录的笔记数量和代表性用途。标记不确定的目录，不擅自解释。

### 2. 归纳

识别重复职责、空目录、混放内容和可能缺失的容器。区分：

- 必须保留的现有目录；
- 可选的新增目录；
- 只有迁移笔记后才有价值的目录；
- 需要用户做决定的冲突。

### 3. 预览

先给出建议目录树，例如：

```text
Vault/
├── 00-Attachments/   # 图片、脚本、模板
├── 01-Projects/      # 有明确交付结果的项目
├── 02-Areas/         # 持续维护的生活与工作领域
├── 03-Resources/     # 常青知识与外部资料
├── 04-Archives/      # 已完成但需要保留的项目与资料
└── 05-Agents/        # 技能与自动化
```

同时列出每个新增目录的理由、是否为空、是否会影响已有链接。

### 4. 确认

向用户确认三件事：

1. 保留哪些现有目录；
2. 创建哪些缺失目录；
3. 是否允许后续迁移、重命名或补索引。

只要用户没有明确授权迁移，就把任务范围限制为创建目录。

### 5. 创建

确认后只创建不存在的目录，并再次输出最终目录树。记录创建清单，不触碰已有笔记内容。

## 冲突处理

- 目录职责重叠：提出“保留并定义边界”或“未来迁移合并”两种方案，不自动合并。
- 同名目录大小写不同：按 macOS 文件系统风险处理，先询问。
- 用户想完全重构：拆成“目录创建”和“笔记迁移”两个阶段，不能一次批量移动。
- Vault 为空：先询问用户最常用的笔记类型和设备，再生成最小结构，不复制完整大 Vault。
- 现有目录非常成熟：只建议补缺，不重新设计整套架构。

## 安全检查

- 创建前确认操作路径是用户的 Vault 根目录，不是技能仓库或临时目录。
- 不删除目录，不覆盖文件，不移动笔记。
- 不把隐藏目录、缓存和同步冲突文件纳入建议结构。
- 创建目录后检查目录是否确实存在，并报告绝对路径。
